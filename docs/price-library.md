# 价格库使用与上线

## 日常使用

1. 打开定价台的“价格数据库”，选择“系统价格库”或“我的价格库”。
2. 选择团体类型及价格表，填写景区/项目和出行日期。项目留空只匹配通用价格；日期留空只匹配无有效期的价格。人数范围以包含免费随行的实际参与人数为准。
3. 点击“采用”，或一次采用全部匹配价格。同名成本或已采用项目会跳过，以免重复计费；要换价，先核对并删除原成本，再采用新的价格。同名多价时请单项选择。
4. 点击页面上方“保存本次估算”，保存成本及价格来源快照。之后更改价格表不会修改已有估算。

## 后台导入

“管理 / 导入价格库”进入 `/prices`。使用已有 Google 登录。普通用户维护自己的价格库；管理员切换“系统价格库”后维护全站可选价格。

支持上传 `.xlsx`、`.csv`、`.tsv`，或粘贴 Excel 表格。Excel 可选工作表。旧版 `.xls` 须另存为 `.xlsx`。文件最多 2 MB，解析后的请求最多 512 KB，一次最多 300 条。CSV 优先 UTF-8，兼容 GB18030。模板下载地址：`/price-template.csv`。

必填表头：团体类型、项目名称、计费方式、单价。选填：分类、数量、批次容量、最低人数、最高人数、备注、仅计入实际成本、景区/项目、生效日期、失效日期。

- 团体类型：学生团、亲子团、老年团、成人团、企业团、自定义。
- 计费方式：固定数量、按参与人数、按容量分批、按成人、按学生/儿童、按家庭组数。
- 单价以人民币元、整次活动为单位；按天报价须先合并活动总天数。零元价格须明确填 `0`，空单价不会当作免费。
- 固定数量使用“数量”；按容量分批使用“批次容量”。其他模式人数由方案自动计算。“最低/最高人数”均指实际参与人数。
- 生效/失效日期为 `YYYY-MM-DD`，包含边界日期；留空表示该侧不限制。
- 系统初始价格及下载模板均为演示数据，正式使用前请管理员替换并停用示例库。

上传后逐行预览；有错误时整批不保存。编辑价格表将生成新版，并停用原版；可停用/恢复价格表。后台保留最近 100 份表的入口。价格库管理状态由服务器检查，不依赖前端隐藏按钮。相同导入请求重试不会生成副本。并发修改时需刷新后重试。

## 部署

本仓库同时支持 Sites 和 Cloudflare Pages；两者的数据库和运行时设置独立，发布代码不会复制数据。

1. 配置服务端环境变量 `PRICE_ADMIN_EMAILS` 为管理员 Google 已验证邮箱，多个邮箱用英文逗号分隔。保持现有 `GOOGLE_CLIENT_ID`。管理员名单不写入公开仓库；未配置时所有账号均不能写系统价格。
2. 保留 `DB` 数据库。已有 `0000`、`0001` 的环境按顺序应用 `0002_price_library.sql` 和 `0003_price_library_versions.sql`。Sites 随版本发布应用迁移；Pages 需在 D1 上执行新增迁移后再部署。不要重新创建数据库或重新执行已应用迁移。
3. 如果旧功能分支曾在某环境运行，旧代码可能在请求中自行建过 `price_catalogs` / `price_items`。此环境必须先核对实际表结构与迁移记录，确认是否已具备 `0002` 的结构；不要盲目重跑建表，也不要删除表。新代码完全依赖迁移，不在请求中修改表结构。
4. `0002` 的原 SQL 保持不变，本次补入缺失的 Drizzle 快照和日志项；新增 `0003` 仅添加带常量默认值的列，兼容已有价格数据。
5. 运行 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm run build:pages`。Sites 使用标准 Worker 构建和 Sites 打包流程；Pages 使用 `dist/client` 及 Advanced Mode Worker。

发布后，用管理员 Google 账号登录 `/prices`，选择系统价格库，上传实际价格表，再返回定价台验证匹配与采用。普通账号应只能维护个人库。真实 Google 交互需要账号本人完成，不通过测试接口绕过登录。
